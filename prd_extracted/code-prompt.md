## 1. 项目概述与技术约束

### 1.1 产品定位

- **名称：** 装修新手SOP全流程Web工具
- **一句话定位：** 半包装修小白的现代中式通关指南 -- 跟着年兽一步步完成装修
- **目标用户：** 25-35岁首次装修的年轻业主，选择半包模式（装修公司负责施工+辅材，业主自购主材）
- **默认风格：** 现代中式（低饱和度暖色调、微水泥、胡桃木、格栅隔断）
- **核心体验时长：** 5分钟闭环体验

### 1.2 DEMO范围 vs 正式版

| 维度 | DEMO版（本次开发） | 正式版（未来扩展） |
|------|-------------------|-------------------|
| 装修模式 | 半包（固定） | 全包/半包/清包可选 |
| 默认风格 | 现代中式（固定） | 多风格可选 |
| 流程自由度 | 强制线性，不可跳步 | 可自由选择步骤 |
| SOP覆盖 | 半包6大阶段20步 | 多模式30+步 |
| AI能力 | 户型识别+合同鉴别+质检（简化） | 全流程分布式AI |
| 养成系统 | 中式房子+水墨年兽 | 虚拟建房进度 |
| 传播机制 | 无 | 社交裂变 |

### 1.3 技术栈

- **框架：** React 18+（函数组件 + Hooks）
- **样式：** Tailwind CSS + CSS变量（Design Tokens）
- **动画：** CSS动画 + GSAP（复杂时序）+ Canvas（水墨粒子效果）
- **状态管理：** React Context + useReducer（全局状态）
- **路由：** 无需路由，单页应用通过状态切换视图
- **部署：** 静态托管（Vercel/Netlify），纯前端无后端

### 1.4 核心痛点数据（产品决策依据）

- 73%的半包业主无法准确预估材料用量
- 68%的装修纠纷源于增项未提前告知
- 28%平均超支比例
- 127小时比价平均耗时
- 68%业主最终结算超预算15%以上

## 4. 功能模块一：对话流风格探测 + 需求采集

### 4.1 功能定义

用户首次进入产品，与水墨年兽进行对话式交互，在90秒内完成风格探测（5题）+ 基础信息采集，最终生成个性化半包装修计划。

### 4.2 对话流状态机

```
开始 → 年兽欢迎语 → 题1（客厅视觉） → 题2（颜色偏好） → 题3（生活方式） 
→ 题4（材质选择） → 题5（最终二选一） → 结果展示 → 基础信息采集（预算/城市/面积/特殊需求）
→ 生成半包计划 → 进入SOP流程
```

### 4.3 5题详细内容

**题1：客厅视觉偏好（4图选择）**
- 年兽问："如果下面四个客厅让你选，你最想住进哪一个？"
- 选项（2x2网格）：
  - 🎋 留白墙面+胡桃木家具
  - 🛋️ 温暖原木+布艺沙发
  - 🏭 裸露管线+冷灰调
  - 🌸 繁花壁纸+水晶吊灯
- 映射权重：选1→现代中式+2，选2→北欧+2，选3→工业+2，选4→轻奢+2

**题2：颜色偏好（3选项单选）**
- 年兽问："关于颜色，你更偏向哪种感觉？"
- 选项：
  - 米白、浅灰、原木色 —— 越素净越好
  - 深蓝、墨绿、暖棕 —— 要有层次感
  - 明亮撞色、活力橙黄 —— 家里要有生气
- 映射权重：选1→现代中式/北欧+1，选2→现代中式/轻奢+1，选3→北欧/工业+1

**题3：生活方式（4选项单选）**
- 年兽问："周末在家，你更喜欢怎么度过？"
- 选项：
  - 阳台泡茶看晨光
  - 开放式厨房做早午餐
  - 窝沙发追剧点外卖
  - 书房看书需要独处
- 映射权重：选1→现代中式+2，选2→北欧+1，选3→轻奢+1，选4→现代中式+1

**题4：材质选择（4选项单选）**
- 年兽问："关于装修材质，你最在意什么？"
- 选项：
  - 微水泥的细腻质感
  - 胡桃木的温暖触感
  - 金属的冷峻光泽
  - 大理石的奢华感
- 映射权重：选1→现代中式+1，选2→现代中式+2，选3→工业+2，选4→轻奢+2

**题5：最终二选一（2图选择）**
- 年兽问："再帮我选最后一组图片，我就告诉你答案~"
- 选项（2x1网格）：
  - 🎋 现代中式（格栅+微水泥）
  - 🛋️ 北欧简约（白墙+原木）
- 映射权重：选1→现代中式+3，选2→北欧+3

### 4.4 结果计算规则

- 预置5种风格结果：现代中式、北欧、日式、轻奢、工业风
- 每题选择累加对应风格的权重分
- 最高分风格为推荐结果，DEMO默认展示"现代中式"
- 展示内容：
  - 风格名称 + 匹配度百分比（DEMO固定87%）
  - 一句话描述（如"追求静气与秩序的东方生活家"）
  - 4个关键词标签（如"留白""胡桃木""格栅""微水泥"）
  - 底部按钮"确认，继续"

### 4.5 基础信息采集（结果页后）

对话流自然过渡，年兽依次询问：
1. **装修预算：** 选项按钮：10万以下 / 10-20万 / 20-30万 / 30万以上
2. **城市：** 城市选择器（一线城市人工费上浮15%，二三线下浮10%）
3. **房屋面积：** 输入框 + 常见户型快捷选择（80/90/100/120/140/160平米）
4. **特殊需求：** 多选：儿童房 / 老人房 / 宠物 / 居家办公 / 智能家居

### 4.6 AI户型图识别（DEMO模拟）

- 在对话流的"户型确认"环节，年兽引导："上传你的户型图，AI帮你自动识别房间数量和面积~"
- DEMO实现：前端模拟上传动画 + 预置识别结果（自动填充房间数量和面积）
- 识别结果自动填充到SOP步骤1的量房沟通中

### 4.7 UI布局要求

- 全屏对话界面，米白背景
- 左侧：年兽头像（32px圆形，朱砂红背景，🐲 emoji）
- 右侧：用户消息靠右，年兽消息靠左
- 选项展示：
  - 4图选择：2x2网格，每张图带圆角8px + 边框hover效果
  - 文字选项：垂直排列，每项前有圆形单选按钮
  - 快捷按钮：胶囊形（border-radius: 16px），黛蓝背景白字
- 结果卡片：顶部显示风格名和匹配度，中部描述，底部4个标签
- 输入区无自由输入，所有交互通过点击选项完成

### 4.8 交互规范

- 渐进式披露：每次只展示1题，答完才出现下一题
- 即时情感反馈：每答2-3题，年兽给出阶段性洞察（"感觉你是个喜欢安静有质感空间的人呢~"）
- 去术语化：选项用生活化语言（"越素净越好"而非"低饱和度色系"）
- 无缝过渡：结果页按钮文案为"确认，继续"而非"生成报告"
- 年兽气泡动画：消息出现时带淡入+轻微弹跳（opacity 0→1, translateY 10px→0, 0.3s ease-out）

**阶段四：泥木工程（锁定中）**

### 5.3 每步结构：五步闭环

| 步骤 | 内容 | 用户操作 |
|------|------|----------|
| 1.年兽引导 | 水墨年兽弹出气泡"接下来我们要做XXX" | 点击"知道了" |
| 2.操作指引 | 展示该步骤的操作指南（做什么+怎么做+验收标准） | 阅读指引 |
| 3.AI辅助 | 场景自动触发AI工具（量房时唤起户型识别/签合同时强制合同鉴别/验收时自动质检） | 按步骤自动唤起 |
| 4.完成确认 | 用户确认已完成，可上传照片佐证 | 点击"已完成" |
| 5.年兽反馈 | 年兽获得灵气，中式房子发生变化，解锁下一步 | 观看动画反馈 |

### 5.4 AI自动触发点

| SOP步骤 | AI功能 | 触发方式 | DEMO实现 |
|---------|--------|----------|----------|
| 步骤1：量房沟通 | AI户型识别 | 自动触发 | 预置识别结果+动画模拟 |
| 步骤3：签订合同 | AI合同鉴别 | 强制触发，不完成无法继续 | 预置风险案例+模拟扫描 |
| 步骤10/12/13/15：验收节点 | AI施工质检 | 自动触发 | 预置照片+模拟检测报告 |

### 5.5 主材采购提醒机制

| 提醒节点 | 提前时间 | 提醒内容 |
|----------|----------|----------|
| 水电改造前 | 3天 | 需确认橱柜方案、PPR水管品牌、地漏型号、开关面板数量 |
| 泥工进场前 | 2天 | 墙地砖需到场、门槛石/窗台石需定制、确认美缝方案 |
| 木工进场前 | 3天 | 木门商家需复测、全屋定制最终方案确认 |
| 油工进场前 | 2天 | 涂料/壁纸需选购、确认色号（自然光+人工光双验证） |
| 安装季 | 5天 | 按顺序预约：厨卫吊顶→橱柜→木门→地板→开关灯具→洁具 |

### 5.6 现代中式风格施工注意点（SOP步骤中的提示）

- **微水泥工艺：** 常用微水泥替代传统涂料，注意基层平整度和养护周期（7天以上）
- **格栅安装节点：** 格栅隔断需在木工阶段同步安装，与吊顶/墙面收口处理提前规划
- **胡桃木材质选择：** 地板、家具、柜体统一胡桃木色系，注意不同批次色差控制
- **无主灯设计：** 推崇无主灯，需在木工吊顶阶段预埋灯槽和变压器位置

### 5.7 UI布局要求

- **SOP主界面：** 左侧垂直时间线（显示20步进度）+ 右侧步骤详情
- **时间线样式：**
  - 已完成：竹青色实心圆 + 绿色连线
  - 当前步骤：黛蓝色实心圆 + 脉冲动画（box-shadow脉冲）
  - 未来步骤：灰色空心圆 + 灰色连线
  - 阶段标签：灰色文字区分6大阶段
- **步骤详情卡片：**
  - 顶部：步骤标题 + 阶段标签
  - 中部：操作指引（文字 + 检查清单）
  - 底部："已完成"按钮（当前步骤）或"已锁定"提示
- **年兽位置：** 页面底部中央，实时显示情绪表情

### 5.8 状态管理逻辑

```typescript
// SOP状态机
const canProceedToStep = (targetStep: number, state: AppState): boolean => {
  // 只能进入下一个未完成的步骤
  return targetStep === state.sopProgress.currentStep + 1;
};

const completeStep = (step: number, state: AppState): AppState => {
  return {
    ...state,
    sopProgress: {
      completedSteps: [...state.sopProgress.completedSteps, step],
      currentStep: step + 1,
      stageUnlockStatus: updateStageUnlock(step, state)
    },
    nianProgress: {
      ...state.nianProgress,
      level: Math.min(24, state.nianProgress.level + 1),
      spiritPoints: state.nianProgress.spiritPoints + 10,
      emotion: 'happy'
    }
  };
};
```

## 6. 功能模块三：半包动态预算管理

### 6.1 五大核心设计原则

1. **预算与SOP强绑定：** 每个SOP步骤关联预算消耗，步骤完成时自动扣减
2. **主材预算与采购联动：** 每个采购节点生成独立子预算，支持记录实际支出
3. **增项书面确认+上限控制：** 增项不得超过合同总额10%
4. **可视化健康度实时反馈：** 铜钱形状进度环 + 三种状态颜色
5. **年兽情感化预警：** 预算超支时年兽从"开心"变"困惑"

### 6.2 功能1：智能预算拆解引擎

| 备用+软装 | 20% | 应急备用、后期软装 |

**城市系数调整：**
- 一线城市：人工费上浮15%
- 新一线：基准
- 二三线：人工费下浮10%

### 12.2 关键实现约束

1. **纯前端实现：** 所有AI功能使用预置数据+动画模拟，无需后端API
2. **状态持久化：** 使用localStorage保存用户进度，刷新页面不丢失
3. **CSS变量优先：** 所有颜色/间距/圆角必须使用CSS变量，禁止硬编码
4. **组件复用：** Button/Card/NianAvatar等基础组件必须在所有视图中复用
5. **动画降级：** 移动端水墨粒子降级为CSS动画，确保流畅性
6. **演示模式隔离：** DemoActor类封装所有演示逻辑，与正常用户模式完全解耦
